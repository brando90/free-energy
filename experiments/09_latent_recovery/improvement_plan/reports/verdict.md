## PART 2 — New attack surface

### MAJOR-1. EXPD's entire d=∞ column is structurally impossible for the attribute quartet — the design contradicts the audit function it swears fail-closed allegiance to.
`audit_truth_status` gives attributes **open-world** semantics: true iff entailed, false iff opposite-signed attribute entailed, else **unknown** (`attribute_not_decidable`) — `expa_global_expansion.py:216–225`, `expc_polarity_control.py:371–380`. CWA applies **only to positive categoricals**. Consequences: (i) `aff_false_attr_∞` / `neg_false_attr_∞` (no refuting rule anywhere) audit **unknown, not false** — the design's "d=∞ = CWA-only falsity" is wrong for attributes; the `assert truth status as designed` audit fails, and the generation-time false-only filter (expa:638 pattern) yields **zero available instances**; (ii) the true cells at ∞ ("aff_true/neg_true × d{0,1,3,∞}") are equally incoherent — entailed-at-∞ means not entailed; (iii) the `planted-token question frequency == 1` audit is independently unsatisfiable at ∞ (the refuting rule head is the only carrier of the token). In this grammar, **attribute truth-decidability ⟺ finite d** — falsity and refutability cannot be decoupled at ∞ for attributes *in principle*. Not fatal because the categorical family (`cat_false_∞`, genuinely CWA-false) already exists to carry the far anchor. **Fix:** delete the attribute-∞ cells; run the attribute gradient over d∈{0,1,2,3,5} only; move every ∞ anchor (H1's ∞-vs-5 contrast, Panel A endpoint, H3's ∞ level) to `cat_false`; print this as a third grammar theorem T3 in the design-matrix table (it's a feature — the same move as T1/T2); optionally add a frequency-matched disconnected-rule attribute cell explicitly labeled unknown-status/exploratory.

### MAJOR-2. `cat_false_usable` as specified cannot measure derivational reuse — H4's confirmatory DV is structurally flat, and Fig-1 Panel A's flagship dotted curve would be ≈0.
The usable rule is "Every zumpus is a C_k." feeding the goal chain. But the validator's poisoned branch fires only for steps **underivable from the true state** (`validator.py:138–142`: derivable-from-state is checked first and classes the step valid). Every chain atom C_k is independently derivable from the premise via closure, so a continuation that visibly reasons "E is a zumpus → E is a C_k" registers **zero** derivational injection-dependence — only the echo ("E is a zumpus") can ever fire, exactly as in the inert cell. The design's "injection-dependence mechanically measurable, poison propagation live" is false as written; usable-vs-inert would be an echo-vs-echo null, and H4's slope would measure echo propensity only. This is precisely the `d45c87be` stated-reliance phenomenon validatorPlan documents (M3) — visible reliance on the lie with an independently-entailed conclusion. Note the legacy 0.342 inj-dep exists *because* `make_falsehood` picks unentailed categories whose closure subtrees contain atoms **not** derivable from the entity's premises. **Fix:** route the usable branch through ≥1 fresh intermediate category ("Every zumpus is a florpus. Every florpus is a C_k." — florpus underivable without a\*), add a world-audit assert (`usable branch contains ≥1 atom ∉ D(true state)`), and pre-register H4's DV as M4-derivational (+ stated-reliance as secondary). Cheap; but if not fixed *now*, the pre-registered H4 dies at first pilot and PLAN2 has to be amended post-timestamp — the worst possible optics.

### MAJOR-3. `gsm8k_gradient.py` does not implement a k-gradient — the regime design's "zero new code, verified implemented" secondary would manufacture an N1-class artifact.
Read in full: `si = select_calc_indices(calcs, point)` depends **only on `point`** (line 111–113,130); the k loop (134–140) merely *filters* (`if remaining < k-1: continue`) and resamples delta. For fixed (instance, point), rows labeled k=1,2,3 have the **same injection site and same steps-remaining**; the only k-dependence in the output is a selection effect (higher k drops short chains) plus delta-resampling noise. The docstring's "k>1 pushes the corruption earlier" (line 8) is unimplemented. The regime design's printed caveat ("its k is steps-remaining-in-chain, goal distance") is itself wrong — k is not even steps-remaining. My own feasibility audit propagated this error ("already implements a GSM8K distance sweep"); the design inherited it. Running it as-is and plotting "early/mid/late × k=1..3" gives a fake parametric axis a code-reading reviewer demolishes. **Fix (~10 lines):** choose `si` such that `remaining == k` (per point-band where feasible), regenerate; or relabel the axis as position-only and drop the k claim. Still cheap (~2–5 GPU-h), still appendix-only — but it is *not* the advertised free asset.

### MAJOR-4. H1's confirmatory slope includes d=0, which the designs' own locked data predict is non-monotone — a pre-registered self-inflicted miss.
Locked: contradiction (d=0) doubt .231/.269/.177 vs one-hop .467/.273/.267 (`paper_results.tex:51–57`) — d=0 < d=1 at early. The causal design knows this (it lists "d=0 non-monotonicity ... discussion pre-registered" as *exploratory*) yet H1 is "judge-doubt slope over d∈{0,1,2,3,5} < 0 (GLMM Wald)". If EXPD's d=0 replicates the dip, the linear logit term is misspecified against the authors' own prior; a low left-endpoint attenuates the negative slope and hands a reviewer "your pre-registered primary assumed the monotonicity your own Table 3 contradicts." **Fix:** primary slope over d∈{1,2,3,5}; d=0-vs-d=1 as its own pre-registered contrast (two-sided, hypothesis explicitly stated as open); isotonic/Cochran-Armitage trend as secondary. Zero cost — it's one paragraph of PLAN2.

### MAJOR-5. EXPG Axis-R (the regime's PRIMARY confirmatory contrast) leaks through the numbered program listing.
Trace lines cite line numbers and the full listing sits in the prompt. If a copy/alias chain's root is a listing **literal** (`x = 7`), the true value is re-readable at O(1) from the listing regardless of trace staleness k_r — effective re-read distance = min(k_r, listing-lookup), and the k_r=1-vs-8 primary contrast can flatten for reasons orthogonal to the construct (the model checks the listing, not the trace). The design never constrains where the refuting value is *stated*. **Fix (one generator constraint):** Axis-R chain roots must be computed values (≥2 listing constants combined), so the trace is the only place the true value appears verbatim; listing-path verification then costs k_c≥1 while trace re-read costs k_r — making k_r the binding dial. Disclose in PLAN_PROGTRACE; add a manipulation check (does doubt cite line numbers from the listing vs the trace?).
