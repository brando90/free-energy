### 1.2 Formal definitions to write (grounded in code)

**World.** A problem instance is `I = (e, C, A, R, F₀, t)`: a single subject entity `e`, category names `C` (the `-pus` nouns), attribute names `A`, rule set `R`, initial facts `F₀`, target literal `t`. Literals: `Cat(e,c)`, `¬Cat(e,c)`, `Attr±(e,a)` — exactly the three predicate shapes in `parse_fact` (validator.py:56–68): `("cat",c)`, `("not_cat",c)`, `("adj",a,pol)`.

**Rule grammar.** `R` contains universally quantified clauses whose body is always a *positive category* and whose head is a category, negated category, or signed attribute — the six surface templates accepted by `parse_rule` (validator.py:33–54): `Every/Each/All X is (a|an) Y`, `… is not (a|an) Y`, `… is (not) adj`, and bare-plural forms `Xes are (not) (Yes|adj)`. State explicitly: **rule bodies are never negative and never attributes** — this single grammatical fact grouns two paper claims (below).

**Closure.** `reach = lfp` of: seed `reach[c] = direct[c]`; propagate `reach[c] ∪= direct[c']` for every positive category `c' ∈ reach[c]` (validator.py:87–105). Formal statement (Prop. A.1): *derivation chains only through positive category atoms; negated-category and attribute heads are absorbing (nothing is derivable from them)*. This is the precise content of the paper's current informal claim "the grammar derives nothing from a negation" (main.tex:197) and of the poisoning-measurability dagger.

**Derivability.** `lit ∈ D(S)` iff `lit ∈ S` or `∃ Cat(e,c) ∈ S` with `lit ∈ reach[c]` (validator.py:107–114). Note in print: derivability is *closure-based* — a single sentence may jump any number of hops (this is what "closure-valid, not strict replay" means; hop-soundness in Part 3 removes it).

**Truth semantics of a planted statement (the CWA answer).** Adopt verbatim from `audit_truth_status` (expa_global_expansion.py:194–225; richer version expc_polarity_control.py:359–394):
- Positive categorical `Cat(e,c)`: **true** iff derivable from `F₀` under closure; otherwise **false by closed-world assumption** (audit basis `unentailed_category_closed_world`). Justify in one sentence: PrOntoQA-OOD worlds are complete by construction, so the intended model makes every unentailed positive categorical false.
- Negated categorical `¬Cat(e,c)`: **false** iff `Cat(e,c)` derivable; otherwise **unknown** (open-world for negations, basis `negated_unentailed_category_open_world`). This deliberate *asymmetry* keeps "genuinely false" families pure — a negation of an unmentioned category is never counted as a falsehood.
- Attribute: true if derivable, false if the opposite-signed attribute is derivable, else unknown.
- **Unknown/unparsed/unavailable injections are excluded at generation time** (expa:638) — so every row in every "false" family is audited-false (`falsehood_false_rate: 1.0`, `all_global_truth_false: true` in RESULTS_LOCK.md:101,107). Print this.

**Step validity and state evolution ("what happens after an invalid step").** Document the exact loop (validator.py:134–149): the state `S` starts as `F₀|e` + marker-stripped prefix facts; each continuation sentence parsed as an entity fact is (i) added to `S` if `∈ D(S)`; (ii) recorded as a *poisoned step* and **also added to `S`** if `∈ D(S ∪ {a*}) \ D(S)` where `a*` is the planted atom (line 140–142); (iii) recorded as *invalid* and **not** added otherwise. Consequences to disclose:
- After the first injection-derived step, its consequences become derivable from `S` and are counted as ordinary valid steps → `n_poisoned` counts **fresh uses**, not all tainted downstream steps (fixed in v2, §1.4-F3).
- Invalid steps do not halt validation; later steps are still checked against the unpolluted-by-invalid state.
- Rule restatements in the continuation are *skipped entirely, true or false* (line 146–147); a fabricated rule is only penalized indirectly when a fact derived from it fails the fact check.

**Injection-dependence detection.** A step is injection-derivable iff derivable with `a*` added but not without. Because rule bodies are positive categories, this fires in exactly two mechanically distinct ways: (i) *derivational use* — `a*` is a positive categorical feeding a rule chain; (ii) *echo* — the step literally restates `a*` (the `a == pred` branch of `derivable`). For negated `a*`, only (ii) is possible — this is why `one_hop_falsehood` shows pooled "poisoned" 0.0156 (echoes, EXPA_REPORT.md) and why the dagger footnote exists. Formalize the split (Part 3, metric M4).

**Final-statement matching.** `final_ok` iff the *last* sentence, marker-stripped and normalized (lowercase, alphanumerics+spaces only), string-equals the target (validator.py:151–153). Disclose: no paraphrase tolerance; any trailing text after the target line ⇒ derailed; only the last sentence is consulted.

**Outcome classification (precedence).** Publish the decision list verbatim (validator.py:155–164):
`unparsed ≻ derailed ≻ injection-dependent ≻ parroted ≻ closure-valid`, plus `generation_failed` upstream of everything for EXPA/B/C (expa:716–717). Two precedence consequences to print: (a) reported injection-dependence is **conditional on reaching the target** — a run that uses the lie and then derails is classed *derailed*; the unconditional "used the injection anywhere" rate is reported separately (Part 3, M4); (b) *parroted* is definitionally "final = target ∧ ≥1 underivable step ∧ no injection-derivable step" — the precise parroted-vs-closure-valid distinction the professor asked for.

**Unparsed.** Sentence-level: an entity-subject-shaped sentence (`^[A-Z]\w*\s+is\b`) that fails the fact grammar (validator.py:148–149) — this includes facts about *other* entities and pronoun subjects ("It is a wumpus"). Non-entity sentences (commentary, questions) are ignored by the parser and affect only the doubt flag. Run-level: ≥1 unparsed sentence ⇒ class `unparsed`. **Denominator convention:** unparsed (and generation-failed) runs are *retained in all denominators*; every table shows the unparsed column (paper_artifacts.py:163–202; expa `summarize_cell`:789–801; RESULTS_LOCK.md:100 "Failed and unparsed generations are retained in denominators and logged"). Appendix A.7 additionally reports headline cells under the parsed-only denominator so reviewers can see both.

**Doubt detection and the stripping-order question.** Answer is favorable and must simply be printed: the doubt regex runs on the **raw, unstripped continuation** (validator.py:167 `DOUBT.search(continuation_text)`); marker stripping (validator.py:23,25–28) applies only on the parse path, per sentence. Additionally the two lexicons are disjoint — `MARKER = {Therefore, Thus, Hence, So, Then, It follows that, We know that, This means}` vs `DOUBT = {wait, however, but, actually, mistake, error, contradict, incorrect, cannot, inconsistent}` — so the order could not change any label. Print both lexicons verbatim in A.5, plus the 32B-judge validation design (doubt_judge.py: all mid-position cohort runs, per-family judge/lexical agreement) and its per-family agreement numbers.

**Cohort and filtering funnel.** Formalize the double filter: instance enters iff (i) the unperturbed greedy rollout ends on the target (`solved`, common.py:56–60) and (ii) that rollout is itself classed closure-valid with empty prefix and no planted atom (validator.py:177–187; expa:620–626). Publish the complete funnel with counts — all numbers already exist: legacy pilot `_cohort: {gold_validated_instances: 168, perturbed_runs_excluded_gold_not_valid: 39}` (results/validated_summary_falsehood.json); EXPA eligibility ladder `{too_few_dataset_steps: 11389, candidate_falsehood_available: 5819, gold_not_solved: 926, gold_not_validator_valid: 1892, no_global_falsehood_candidate: 1753, too_few_model_intermediate_steps: 64, achieved: 150}` (RESULTS_LOCK.md:106); EXPC availability ladder (RESULTS_LOCK.md:104). **Refutation distance (formalizing "local falsifiability").** Adopt EXPC's `shortest_rule_distance` (expc:340–358) as the paper-level definition: `d(a*) =` BFS depth, over *direct* rule applications from the prefix state, needed to derive the complement of `a*`; `d = 0` (complement already stated) = contradiction family; `d = 1` = negated-step/one-hop; `d = k` = neghop-k; `d = ∞` (complement underivable; falsity certified only by CWA closure search) = global falsehood. This single definition unifies families (a)–(f) and the dose-response, is already logged per-row in EXPC (`local_rule_distance`), and is retroactively computable for every logged injection (Part 3, M5). It also gives weakness #1 its parametric variable for free.

**Grammar-inherited details to state once.** Singularization = strip trailing "es" (validator.py:30–31) — safe for `-pus/-puses` categories; entity identification = first token of the rollout's first sentence (validator.py:200; expa:622–624) — failure degrades to unparsed, never to silent misvalidation; sentence splitting = `(?<=\.)\s+` (common.py:50–53).

## PART 2 — Terminology replacement map

### 2.1 Definitions box (new, main text §3; also the paper's controlled vocabulary)

> **Outcome classes (mutually exclusive, precedence-ordered):** *generation-failed*; *unparsed*; *derailed* (final ≠ target); *injection-dependent* (≥1 step derivable only via the planted atom; final = target); *parroted* (final = target despite an underivable step); *closure-valid completion* (every step entailed by true premises + prior valid steps under rule closure; final = target).
> **Orthogonal flags:** *verbalized doubt* (lexical detector, judge-validated); *targeted flag* (doubt referencing the planted claim); *corrective re-derivation* (continuation re-states the true version of the overwritten step); *goal-jump* (target stated with no intermediate derived facts); *stated reliance* (justification cites the planted atom); *hop-sound* (every step one rule application from prior state).
> **Composites:** *strict repair* = targeted flag or corrective re-derivation, ∧ closure-valid ∧ ¬goal-jump ∧ ¬stated reliance. *Routing around the error* = closure-valid ∧ ¬stated reliance ∧ ¬targeted flag (silent circumvention). *Silent absorption* = injection-dependent ∧ ¬verbalized doubt.
> **Refutation distance** d: minimum number of direct rule applications, from the visible prefix state, needed to derive the complement of the planted claim (d=∞: falsity certifiable only by full-closure search).

### 2.2 Usage rules

- **"recovery" / "recover"**: banned as a metric term. Permitted only: (i) scare-quoted for naive final-answer accuracy ("final-answer 'recovery'"); (ii) verbatim in citations/related work; (iii) "unrecoverable/unrecoverability" when discussing the compounding-error *premise* under attack. Every other instance → a defs-box term.
- **"repair"**: permitted **only** for *strict repair* as defined (this instantiates the professor's rule: "indicates correction or logically routes around" — we split his disjunction into *strict repair* vs *routing around* because they are behaviorally and mechanistically different, and the Llama/OLMo result shows they dissociate).
- **"recoverability"** (task property) → **"derivational redundancy"** (of the task's proof structure).
- **"absorbed/absorption"** → *injection-dependent / uses the planted step*; keep "silent absorption" only as the defined composite.
- Repo/dir name `latent_recovery` and `experiments/09_latent_recovery`: keep (renaming breaks locked paths), add one repro-section footnote that the historical name predates the terminology.

## PART 3 — New stricter metrics from existing logs (zero GPU)

All inputs already exist on disk (sha-locked): legacy families `results*/perturbed*/runs.jssonl` rows carry `{id, point, sent_idx, correct_step, corrupted_step, continuation, recovered, n_steps_gold}` (perturb.py:119–125) joined to `data/pilot.jsonl` (question/target) and `results/gold/rollouts.jsonl` (gold steps); EXPA/EXPB/EXPC `validated_outputs.jsonl` + `manifest.jsonl` carry `{question, target, entity, sent_idx, prefix_steps, original_gold_proof/steps, injected_statement, truth_audit, continuation}` (expa:514–537, 693–735; expc:853–930). The world model is reconstructed per row by `parse_world` + `closure`. Everything below is a pure re-analysis.

**M1 — Strict repair rate (SRR).** Defined for audited-false injections only. A run is a strict repair iff **all** of:
(a) **targeted flag OR corrective re-derivation**. Targeted flag: some sentence containing a DOUBT token, in a ±2-sentence window, mentions the planted predicate lemma (category/attribute word of `a*`) — regex over raw continuation, planted predicate extracted by `parse_statement_for_audit`. Corrective re-derivation: the complement of `a*` (equivalently the overwritten `correct_step`) appears as a parsed step and is true-derivable — exactly `audit.py:161`'s `rederive_correct` (`any(norm(s) == norm(steps[si]) for s in cont)`), generalized to normalized-literal rather than string match.
(b) class = closure-valid.
(c) ¬goal-jump: ≥1 intermediate derived entity-fact before the final line (`audit.py:156–160`'s `jump0 == False`).
(d) ¬stated reliance (M3).
Report SRR per family × position, plus the decomposition (a)-only, (b)-only rates so reviewers see which conjunct binds. Also report the permissive-vs-strict gap explicitly.

**M2 — Goal-jump rate and hop-soundness.** Goal-jump: zero intermediate parsed entity-facts before the final target line (already computed for the legacy wrong family at 4.7–9.2% in audit.py section A — promote to *every* cell). Hop-sound: re-validate each continuation with `derivable` restricted to the **direct** rule map (`direct_rule_map`, expc:230–235; i.e., `direct` instead of `reach`) — a step is hop-sound iff one rule application from prior state; a run is hop-sound-valid iff closure-valid ∧ every step hop-sound. Report `hop-sound valid` next to `closure-valid`: this is the honest "no skipped derivations" number the professor's #4 demands.

**M3 — Stated-reliance flag.** In canonical PrOntoQA style, proofs alternate rule/fact. Flag a run iff some parsed fact `Q(e)` is immediately preceded by a rule sentence with body = the planted category and head = Q, with `Q(e)` not derivable from `S_true` *at that point without* `a*` — or, weaker disclosed variant, even when independently derivable (the `d45c87be` case: visibly reasoning from the lie to a coincidentally-true conclusion). Report both variants; use the strong variant in SRR conjunct (d), report the weak one descriptively.
